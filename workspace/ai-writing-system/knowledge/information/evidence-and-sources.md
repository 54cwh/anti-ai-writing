# Evidence and Sources
## 信息需求、证据管理与信息来源

## 1. 文件目的

本文件研究写作过程中信息的获取、识别、核实和使用，以及模型如何根据当前任务判断信息是否充分。

写作需要建立在一定的信息基础之上。无论是描述事实、解释现象、分析原因，还是形成评价和结论，都需要相应的信息支持。

AI 写作中存在一个值得关注的问题：模型在缺少必要信息时，仍然可能继续生成完整的文字。

例如：

用户要求总结一次校园志愿活动，但只提供了活动名称。

模型却生成了活动组织过程、参与者反馈和活动成效。

这些内容可能符合常见活动总结的表达习惯，却不一定符合实际情况。

模型需要认识到，语言生成能力无法替代缺失的信息。

本文件重点研究：

1. 信息与证据的基本含义。
2. 不同类型的信息及其用途。
3. 写作任务的信息需求识别。
4. 信息缺口的发现与分类。
5. 信息来源及其可靠性。
6. 证据与具体判断之间的对应关系。
7. 信息检索与资料核实。
8. 多来源信息的交叉验证。
9. 不同来源之间的冲突处理。
10. 用户提供信息的使用。
11. 主动询问机制。
12. 信息不足时的任务处理。
13. 共享知识库的信息管理。
14. 各代理之间的信息传递。
15. 信息使用的质量评价。

本文件主要服务于 Researcher，同时为 Prompt Architect、Logic Analyst、Writer 和 Evaluator 提供共同的信息管理框架。

**核心目标：让模型能够识别完成任务所需要的信息，明确现有材料能够支持什么判断，并在信息不足时主动获取必要资料或向用户提出问题。**

## 2. 信息与证据

### 2.1 什么是信息

信息是模型理解任务、认识对象和开展分析所需要的内容。

信息可以包括：

- 事实。
- 数据。
- 文件。
- 研究成果。
- 案例。
- 访谈记录。
- 观察结果。
- 用户提供的背景。
- 历史记录。
- 专业知识。
- 制度规定。

不同信息承担不同的作用。

例如，研究企业创新产出时：

- 企业专利数据提供创新产出信息。
- 企业研发投入数据提供资源投入信息。
- 企业公告提供经营活动信息。
- 学术论文提供理论和研究依据。
- 企业访谈提供具体研发过程的信息。

### 2.2 什么是证据

证据是能够支持、限制或反驳某项判断的信息材料。

信息与证据之间存在区别。

例如：

某份企业年报包含企业研发人员数量。

这是一项信息。

如果文章需要判断企业研发人员规模是否扩大，那么连续年份的研发人员数量可以成为支持这一判断的证据。

如果文章需要判断企业创新能力是否提高，仅凭研发人员数量增加就不够。

因此，某项信息能否成为有效证据，需要结合具体判断考察。

### 2.3 证据具有针对性

证据需要对应明确的判断。

例如：

| 信息材料 | 可以支持的判断 | 无法直接支持的判断 |
|---|---|---|
| 企业研发投入增加 | 研发投入规模扩大 | 创新能力必然提高 |
| 专利申请数量增加 | 专利申请活动增加 | 专利技术价值提高 |
| 员工满意度调查 | 样本员工的满意度情况 | 所有员工都满意 |
| 活动参与人数 | 活动参与规模 | 活动实际影响力 |
| 企业营业收入增长 | 营业收入增加 | 企业经营效率提高 |
| 政策正式发布文件 | 政策内容及发布时间 | 政策已经取得成效 |

模型需要根据证据的实际内容决定能够形成什么判断。

### 2.4 证据具有不同用途

证据可以用于：

**事实确认**

确认某件事情是否发生。

**现象描述**

说明某种变化或现象。

**关系分析**

识别不同变量、事件或主体之间的联系。

**机制解释**

帮助说明某种变化如何产生。

**比较分析**

比较不同对象或不同时间的情况。

**观点评价**

根据明确标准评价某项行为或结果。

**结论检验**

检查已有判断是否得到材料支持。

### 2.5 基本原则

- 根据具体判断确定需要什么信息。
- 判断材料是否真正支持当前观点。
- 区分事实信息与研究证据。
- 明确证据能够支持的内容。
- 根据证据的实际用途组织论述。

## 3. 信息需求识别

信息获取应当从任务本身开始。

模型需要先明确完成当前任务需要解决什么问题，再确定需要哪些材料。

### 3.1 从写作目标出发

例如：

用户要求撰写一篇关于某项政策对企业创新影响的研究报告。

模型需要识别：

- 政策具体内容。
- 政策实施时间。
- 政策覆盖对象。
- 企业创新指标。
- 企业实际参与情况。
- 可能的作用机制。
- 相关研究和理论依据。

这些信息分别服务于政策介绍、研究设计、事实分析和结论形成。

### 3.2 将任务拆分为具体问题

例如：

研究飞地经济对上市公司创新产出的影响。

可以拆分为：

| 具体问题 | 所需信息 |
|---|---|
| 哪些地区实施了飞地经济政策？ | 官方政策文件、园区资料 |
| 政策何时开始实施？ | 政策发布日期、园区揭牌时间、实际运营时间 |
| 哪些企业参与了项目？ | 入驻名单、企业公告、政府公开资料 |
| 企业创新产出如何变化？ | 专利申请、发明专利等数据 |
| 企业如何受到政策影响？ | 企业参与情况、资源流动、技术合作等资料 |
| 如何解释研究结果？ | 理论研究、已有文献、实际案例 |

### 3.3 区分必要信息与辅助信息

必要信息直接影响任务能否完成。

辅助信息可以改善分析深度，但不会直接决定核心判断能否成立。

例如：

研究某个飞地园区的政策效应时：

- 园区启动时间属于必要信息。
- 政策覆盖对象属于必要信息。
- 企业实际参与情况可能属于必要信息。
- 园区建筑面积可以作为背景信息，但未必影响核心识别。

模型应当优先获取必要信息。

### 3.4 建立信息需求清单

| 信息项目 | 用途 | 重要程度 | 当前状态 |
|---|---|---|---|
| 政策启动时间 | 确定处理时点 | 高 | 待核实 |
| 企业入驻名单 | 识别处理对象 | 高 | 缺失 |
| 专利申请数量 | 衡量创新产出 | 高 | 已获得 |
| 园区面积 | 描述项目规模 | 低 | 未获取 |
| 相关研究 | 建立理论依据 | 高 | 部分获得 |

### 3.5 信息需求的动态变化

信息需求会随着分析深入而变化。

例如：

最初需要确认某企业是否入驻园区。

找到相关公告后，进一步发现公告只说明企业参加了园区举办的活动。

这时需要继续核实企业是否正式入驻。

因此，信息需求应当根据新获得的材料持续更新。

### 3.6 基本原则

- 从任务目标提取信息需求。
- 将宽泛问题拆分为可核实的问题。
- 优先识别影响核心判断的信息。
- 区分必要信息与辅助信息。
- 根据新获得的材料更新信息需求。

## 4. 信息缺口的识别与分类

信息缺口是指完成当前任务所需要的信息尚未获得，或者现有材料无法满足相应的判断要求。

### 4.1 事实缺口

不知道某件事情是否发生。

例如：

目前无法确认某企业是否正式入驻某个园区。

需要查找：

- 企业公告。
- 园区名单。
- 政府公开文件。
- 相关主体的正式说明。

### 4.2 时间缺口

知道某件事情发生，但无法确定具体时间。

例如：

知道某园区已经开始运营，却不知道实际运营时间。

需要进一步区分：

- 政策发布。
- 项目签约。
- 园区揭牌。
- 正式运营。
- 首批企业入驻。

不同时间可能对应不同的研究含义。

### 4.3 对象缺口

知道某项活动或政策存在，但无法明确具体涉及哪些主体。

例如：

某项政策覆盖多个地区，但缺少完整地区名单。

### 4.4 数据缺口

缺少分析所需要的数据。

例如：

研究企业创新产出，却没有获得专利申请数据。

### 4.5 定义缺口

某个变量或概念缺少明确的定义和测量口径。

例如：

不同资料对企业数字化转型的测量方式存在差异。

需要明确采用哪一种定义。

### 4.6 过程缺口

知道某项活动或变化已经发生，却不了解具体过程。

例如：

某企业与园区建立了合作关系，但不知道合作涉及研发、生产还是人才交流。

### 4.7 机制信息缺口

缺少解释某种关系如何产生的信息。

例如：

企业参与园区项目后创新产出增加，但没有获得企业实际获得哪些研发资源的资料。

### 4.8 来源缺口

已经获得某项信息，却无法确认其来源。

例如：

某篇文章提到园区首批入驻了十家企业，但没有提供名单或官方出处。

### 4.9 反面证据缺口

当前材料主要支持某项判断，却没有检查可能与该判断冲突的信息。

例如：

研究某项政策的积极效果时，没有考察同期其他政策或不利影响。

### 4.10 信息缺口与推理缺口

两者需要明确区分。

信息缺口：

不知道某企业是否实际入驻园区。

推理缺口：

已经确认企业入驻园区，但尚未解释入驻行为如何影响创新产出。

前者需要获取信息。

后者需要开展逻辑和机制分析。

两者也可能同时存在。

### 4.11 缺口记录

| 当前问题 | 缺口类型 | 缺少内容 | 处理方向 |
|---|---|---|---|
| 企业是否正式入驻 | 事实缺口 | 正式入驻证据 | 查找园区名单 |
| 园区何时运营 | 时间缺口 | 实际运营日期 | 核对官方材料 |
| 企业创新产出 | 数据缺口 | 专利数据 | 获取数据库资料 |
| 政策如何影响创新 | 机制信息缺口 | 实际作用过程 | 检索研究、案例 |
| 园区企业名单 | 对象缺口 | 完整企业名单 | 查找政府公示 |

### 4.12 基本原则

- 将信息缺口定位到具体问题。
- 区分信息缺口与推理缺口。
- 明确缺失内容对任务的影响。
- 根据缺口类型选择获取方式。
- 保留尚未解决的缺口记录。

## 5. 信息来源及其特点

不同来源能够提供的信息不同。

模型需要根据任务选择合适的信息来源。

### 5.1 用户提供的信息

包括：

- 用户直接描述。
- 用户上传的文件。
- 用户提供的数据。
- 用户补充的背景。
- 用户此前确认的决定。

这类信息对于了解用户的实际任务、内部情况和个人经历尤其重要。

例如：

用户要求撰写一次活动总结，但活动的具体组织过程没有公开资料。

用户提供的活动记录可能是最直接的信息来源。

### 5.2 官方文件

包括：

- 政府公告。
- 政策文件。
- 法律法规。
- 企业公告。
- 官方统计公报。
- 机构公开报告。

这类来源适合核实正式制度、政策时间、组织名单和公开事实。

### 5.3 数据库

包括：

- 学术数据库。
- 企业数据库。
- 金融数据库。
- 政府统计数据库。
- 行业数据库。

数据库适合提供结构化数据和长期观测资料。

使用时需要明确：

- 数据来源。
- 统计口径。
- 时间范围。
- 样本范围。
- 变量定义。
- 数据更新情况。

### 5.4 学术文献

包括：

- 期刊论文。
- 学位论文。
- 学术专著。
- 会议论文。
- 工作论文。

学术文献可以提供：

- 理论解释。
- 研究方法。
- 变量定义。
- 实证证据。
- 研究争议。
- 已有研究的局限。

使用时需要区分作者的研究发现、理论观点和推测。

### 5.5 新闻报道

新闻报道可以提供：

- 事件发生情况。
- 项目进展。
- 企业活动。
- 人物访谈。
- 公开信息线索。

新闻资料尤其适合帮助发现进一步核实的方向。

涉及正式名单、关键日期和政策效力时，应尽可能寻找原始材料。

### 5.6 专业机构报告

包括：

- 行业研究报告。
- 咨询报告。
- 专业协会报告。
- 国际组织报告。

这些资料可以提供行业背景、市场趋势和专业分析。

需要关注报告的方法、样本和数据来源。

### 5.7 访谈与观察资料

包括：

- 人物访谈。
- 企业访谈。
- 现场观察。
- 问卷调查。
- 工作记录。

这些资料可以补充公开文件难以呈现的实际过程和参与者经验。

使用时需要明确资料的采集方式和适用范围。

### 5.8 其他来源

还可能包括：

- 专业论坛。
- 社区讨论。
- 公开社交媒体内容。
- 项目文档。
- 内部工作记录。

这些来源可以提供线索和具体经验。

模型需要根据来源特点决定其用途，并核实关键事实。

### 5.9 来源选择原则

来源选择需要结合信息类型。

例如：

| 信息需求 | 优先考虑的来源 |
|---|---|
| 政策发布日期 | 官方政策文件 |
| 企业财务数据 | 企业年报、专业数据库 |
| 园区正式名单 | 政府文件、园区公告 |
| 学术理论 | 原始学术文献 |
| 行业发展趋势 | 统计数据、专业报告 |
| 活动实际过程 | 用户记录、现场材料 |
| 人物实际经历 | 当事人提供的信息 |
| 社会反馈 | 访谈、调查、公开讨论 |

不存在适用于所有任务的固定来源排名。

模型需要根据具体事实选择最接近原始信息的来源。

## 6. 信息来源的可靠性评价

找到信息之后，还需要判断它是否适合当前任务。

### 6.1 来源身份

首先确认：

- 谁发布了这份材料？
- 发布者是否了解相关事实？
- 发布者是否具有相应的专业能力？
- 是否存在明确的利益关系？

例如：

政府部门发布的政策文件适合确认政策内容。

企业宣传材料可以说明企业如何介绍自身业务，但未必适合独立评价企业实际经营效果。

### 6.2 原始性

尽量寻找原始信息。

例如：

一篇新闻报道引用某份政府文件。

如果研究需要确认政策具体内容，应当尽量找到原始政府文件。

原始材料可以减少信息在转述过程中产生的偏差。

### 6.3 时间适用性

检查信息是否适用于当前任务。

例如：

企业当前股权结构与五年前的股权结构可能不同。

如果研究需要使用2020年的企业股权数据，应当寻找对应年份的材料。

### 6.4 完整性

检查资料是否提供了足够的背景。

例如：

一项调查只公布了满意度比例，却没有说明样本数量和调查对象。

这会限制其解释价值。

### 6.5 方法透明度

涉及研究数据和调查结论时，需要检查：

- 样本如何选择？
- 数据如何收集？
- 指标如何计算？
- 分析方法是什么？
- 是否说明研究限制？

### 6.6 独立性

多个来源引用同一份原始材料，并不代表获得了多个独立证据。

例如：

五篇新闻都引用同一份企业宣传稿。

它们在信息来源上仍然具有共同依赖。

模型需要识别信息来源之间的关系。

### 6.7 利益关系

不同来源可能具有不同的发布目的。

例如：

企业宣传材料可能强调自身优势。

政策宣传材料可能重点介绍政策成果。

这些材料仍然具有信息价值，但模型需要结合其他资料进行判断。

### 6.8 可靠性评价记录

| 评价维度 | 核查问题 |
|---|---|
| 来源身份 | 发布者是谁？ |
| 原始性 | 是否接近原始材料？ |
| 时间 | 是否符合研究时间要求？ |
| 完整性 | 是否包含必要背景？ |
| 方法 | 数据如何产生？ |
| 独立性 | 是否依赖其他来源？ |
| 利益关系 | 发布者是否具有特定立场？ |
| 可核实性 | 是否能够追溯原始内容？ |

### 6.9 基本原则

- 根据任务选择来源。
- 优先获取接近原始事实的材料。
- 检查资料的时间和适用范围。
- 识别不同来源之间的依赖关系。
- 根据来源特点确定其能够承担的证据作用。

## 7. 建立判断与证据之间的对应关系

模型需要知道每项判断由什么材料支持。

### 7.1 判断与证据对应表

例如：

| 文章判断 | 支持材料 | 支持程度 | 待解决问题 |
|---|---|---|---|
| 园区于2018年启动 | 官方揭牌公告 | 支持启动时间 | 实际运营时间待核 |
| 企业正式入驻园区 | 园区企业名单 | 直接支持 | 无 |
| 企业创新产出增加 | 专利数据库 | 支持数量变化 | 专利质量尚未衡量 |
| 政策提高创新能力 | 专利变化及政策资料 | 尚需进一步分析 | 因果识别与作用机制 |

### 7.2 建立证据链

一项重要判断可能需要多个材料共同支持。

例如：

判断某企业受到某项政策影响。

可以建立：

```text
政策文件
   |
   v
确认政策内容和实施时间
   |
   v
企业参与证明
   |
   v
确认企业实际受到政策覆盖
   |
   v
企业经营和创新数据
   |
   v
观察企业后续变化
   |
   v
进一步开展影响分析
```

这里不同材料承担不同任务。

政策文件不能单独证明企业已经受到政策影响。

企业入驻证明也不能单独证明政策提高了企业创新产出。

### 7.3 证据强度与判断强度

模型需要检查：

- 证据是否直接对应判断？
- 是否需要多个来源共同支持？
- 是否存在其他解释？
- 当前材料是否足以形成结论？

### 7.4 证据不足时的处理

如果材料只能支持部分判断，应当保留已经获得支持的内容，并将缺失部分转化为进一步的信息需求。

例如：

已经确认企业入驻园区，但尚未获得企业参与研发合作的资料。

可以确认企业入驻情况。

但不能直接认定企业通过园区获得了研发资源。

### 7.5 基本原则

- 为重要判断建立证据对应关系。
- 明确不同材料的证据作用。
- 识别证据链中的缺失环节。
- 区分直接证据与间接线索。
- 根据证据情况确定判断范围。

## 8. 信息检索与核实

Researcher 负责根据任务需求获取外部信息。

### 8.1 明确检索问题

检索之前，需要明确：

- 要确认什么事实？
- 需要什么类型的资料？
- 资料应该来自哪里？
- 需要覆盖什么时间范围？
- 最终要支持哪项判断？

### 8.2 将问题转换为检索任务

例如：

需要确认某企业是否入驻常熟（北京）创新中心。

可以拆分为：

1. 查找创新中心官方企业名单。
2. 查找政府发布的入驻企业信息。
3. 查找企业自身公告。
4. 查找企业与园区的正式合作信息。
5. 核对企业名称和时间。

### 8.3 优先寻找原始来源

例如：

检索结果中出现一篇新闻，提到某企业参与园区项目。

下一步需要检查：

- 新闻是否引用官方材料？
- 是否存在园区原始公告？
- 企业是否公开确认？
- 参与项目是否等于正式入驻？

### 8.4 交叉验证

对于重要事实，可以寻找多个独立来源进行核实。

例如：

某园区的揭牌时间。

可以比较：

- 政府新闻。
- 园区官网。
- 当地政府工作报告。
- 项目建设资料。

如果多个独立来源指向同一时间，事实确认的基础会更加充分。

### 8.5 区分不同时间

研究政策或项目时，需要注意：

- 文件发布日期。
- 政策生效日期。
- 项目签约日期。
- 项目揭牌日期。
- 正式运营日期。
- 首批入驻日期。

这些时间具有不同含义。

不能因为它们都与项目启动有关，就直接互相替代。

### 8.6 保存检索记录

Researcher 应当记录：

| 项目 | 内容 |
|---|---|
| 检索问题 | 需要确认的具体事实 |
| 检索关键词 | 实际使用的检索词 |
| 来源名称 | 资料发布主体 |
| 原始出处 | 原始文件或网页 |
| 发布时间 | 资料发布时间 |
| 涉及时间 | 事实发生时间 |
| 核心内容 | 资料提供的信息 |
| 证据用途 | 支持哪项判断 |
| 核实情况 | 已确认、部分确认或待核实 |

### 8.7 停止检索的条件

检索需要围绕任务目标展开。

当以下条件得到满足时，可以结束当前检索：

- 已获得能够支持当前判断的材料。
- 关键时间和对象已经核实。
- 主要来源已经记录。
- 尚未解决的问题已经明确。
- 继续检索不会实质改变当前判断。

如果关键事实仍然无法确认，需要记录检索限制，而不是通过推测补齐。

## 9. 多来源信息的冲突处理

不同来源可能提供不同信息。

模型需要识别差异，并分析差异产生的原因。

### 9.1 时间冲突

例如：

一份资料显示某园区于2017年揭牌，另一份资料显示2018年正式运营。

这两项信息可能分别对应不同事件，并不一定相互矛盾。

需要确认：

- 揭牌时间。
- 实际运营时间。
- 首批企业入驻时间。

### 9.2 数值冲突

例如：

不同报告对某项经济指标给出了不同数值。

需要检查：

- 统计口径。
- 统计时间。
- 数据来源。
- 单位。
- 修订情况。
- 样本范围。

### 9.3 概念口径冲突

例如：

不同研究对企业数字化转型的定义不同。

需要比较：

- 理论定义。
- 指标构造。
- 数据来源。
- 研究目的。

### 9.4 事实描述冲突

例如：

企业公告称已完成项目合作，新闻报道却称项目仍处于建设阶段。

需要确认：

- 双方描述的是不是同一项目？
- 合作是否包含不同阶段？
- 信息发布时间是否不同？
- 是否存在后续调整？

### 9.5 证据优先级

处理冲突时，可以重点考察：

1. 来源是否接近原始事实？
2. 来源是否具有明确的信息获取渠道？
3. 资料是否与当前问题直接相关？
4. 发布时间是否符合当前核查要求？
5. 是否存在独立来源支持？
6. 不同来源的统计口径是否一致？

### 9.6 保留无法消除的差异

如果现有资料无法解释冲突，需要明确记录。

例如：

「现有资料分别记载了园区揭牌和正式运营的不同时间，尚未找到能够确认实际开始运营日期的官方材料。」

这种处理能够保留真实的信息状态。

## 10. 用户提供的信息与主动询问

这是本文件需要重点解决的问题。

AI 并不总是拥有完成任务所需要的信息。

有些信息存在于用户的个人经历、工作过程、内部文件和未公开资料中。

模型无法通过一般公开检索获得这些内容。

因此，询问用户是信息获取过程中的正常环节。

### 10.1 用户掌握的信息类型

用户可能掌握：

- 个人经历。
- 真实事件经过。
- 内部工作安排。
- 尚未公开的项目情况。
- 具体活动成果。
- 对某个问题的实际认识。
- 任务背后的真实目的。
- 未写入文档的背景条件。
- 个人希望保留的观点和表达。

这些信息可能直接影响文章的正确性。

### 10.2 模型需要判断是否应该询问

以下情况适合向用户询问。

**情况一：关键事实只有用户掌握。**

例如：

用户要求总结一次内部活动，但没有提供活动实际过程。

**情况二：任务存在多种合理解释。**

例如：

用户要求修改文章，但没有明确希望突出研究发现、理论解释还是政策建议。

**情况三：缺少的信息会改变核心判断。**

例如：

某项政策究竟在2018年开始执行，还是2019年开始执行，会直接影响研究设计。

**情况四：用户掌握尚未提供的材料。**

例如：

模型需要根据用户的原始数据形成分析，但当前没有获得数据文件。

**情况五：用户的真实意图无法从现有内容确定。**

例如：

用户要求撰写一段活动总结，但模型无法判断其希望强调参与人数、组织过程还是活动意义。

### 10.3 什么时候优先检索

如果缺少的信息属于公开事实，且能够通过可靠来源获取，通常可以先检索。

例如：

- 政策发布日期。
- 企业公开信息。
- 公开统计数据。
- 学术研究。
- 法律法规。

不需要将所有信息需求都转化为用户问题。

### 10.4 什么时候不应该自行补全

当模型无法获得必要信息时，需要将缺口明确交给用户。

例如：

用户要求写一篇个人志愿经历总结，却没有说明自己实际承担了哪些工作。

模型不能根据常见志愿者经历自行编造。

### 10.5 询问需要具有针对性

提问应当直接对应当前缺失的信息。

不推荐：

「请提供更多背景，以便我更好地完成任务。」

推荐：

「这次活动中，你实际负责的是现场引导、献血登记，还是活动统筹？我需要确认具体职责，才能准确描述你的工作内容。」

第二种提问明确说明了：

- 当前缺少什么。
- 为什么需要这项信息。
- 用户需要补充什么。

### 10.6 控制提问数量

模型应当优先询问最影响任务完成的问题。

如果一个问题已经足以确定后续工作方向，就先询问这个问题。

对于能够通过检索解决的内容，交给 Researcher。

对于不会影响核心判断的细节，可以根据已有信息继续完成任务，并保留必要的说明。

### 10.7 询问与假设的关系

某些信息缺口不会实质改变任务方向。

此时可以采用明确的工作假设继续推进。

例如：

「以下分析暂按政策于2019年正式实施处理，后续需要根据官方文件核实。」

但如果不同假设会改变核心结论或研究设计，就应当优先向用户询问或查找原始资料。

### 10.8 主动询问流程

```text
发现信息缺口
      |
      v
判断信息是否公开
      |
   +--+--+
   |     |
   v     v
  公开   非公开或用户掌握
   |     |
   v     v
Researcher   判断是否影响核心任务
检索核实          |
             +---+---+
             |       |
             v       v
            影响    影响较小
             |       |
             v       v
          询问用户  建立工作假设
             |       |
             +---+---+
                 |
                 v
             更新信息
                 |
                 v
             继续任务
```

### 10.9 基本原则

- 将用户视为重要的信息来源。
- 公开事实优先通过检索核实。
- 私人经历和内部情况通过用户获取。
- 提问直接对应具体的信息缺口。
- 说明问题与当前任务之间的联系。
- 根据缺口的重要程度决定是否暂停任务。
- 让用户补充的信息进入共享知识库。

## 11. 信息不足时的任务处理

信息不足并不意味着整个任务无法推进。

模型需要判断哪些部分能够继续，哪些部分需要等待补充。

### 11.1 区分可完成与待补充的内容

例如：

用户要求撰写一篇研究报告，但没有提供完整的企业专利数据。

当前仍然可以完成：

- 研究背景。
- 理论分析。
- 变量设计。
- 数据需求说明。
- 研究方法讨论。

暂时无法完成：

- 实际回归结果。
- 具体系数解释。
- 稳健性检验结果。
- 最终实证结论。

### 11.2 建立任务状态

| 任务部分 | 当前状态 | 处理方式 |
|---|---|---|
| 研究背景 | 可以完成 | 使用现有资料 |
| 理论分析 | 部分完成 | 补充文献 |
| 数据整理 | 待补充 | 请求数据 |
| 实证分析 | 暂停 | 等待数据 |
| 结果解释 | 暂停 | 等待实证结果 |

### 11.3 避免用推测填补空白

当模型无法获得某项数据时，可以：

- 明确指出缺少什么。
- 说明这一缺口影响哪些分析。
- 提供数据获取建议。
- 先完成其他能够独立推进的部分。

### 11.4 将信息需求转化为下一步工作

例如：

「目前已经确认政策启动时间，但尚未获得完整企业名单。下一步需要查找园区正式入驻企业公告，并将企业名称与上市公司数据库进行匹配。」

这比笼统地说「资料仍不充分」更有操作价值。

### 11.5 基本原则

- 根据现有信息划分任务状态。
- 推进已经具备条件的工作。
- 暂停依赖关键缺失信息的判断。
- 明确缺口对后续工作的影响。
- 将信息需求转化为具体任务。

## 12. 信息来源与证据的记录管理

信息需要在后续写作和修改过程中持续使用。

因此，项目需要建立可追溯的信息记录。

### 12.1 建立来源记录

建议使用以下结构：

```text
knowledge/
└── information/
    ├── evidence-and-sources.md
    └── sources/
        ├── README.md
        ├── source-index.md
        └── research-notes/
```

其中：

- `source-index.md`：记录重要信息来源。
- `research-notes/`：保存具体检索成果和资料分析。

具体项目资料可以保存在项目自己的工作目录中。

### 12.2 来源记录格式

```markdown
# Source Record

## 基本信息

- 来源名称：
- 发布主体：
- 发布时间：
- 原始链接：
- 资料类型：

## 核心内容

- 

## 可以支持的判断

- 

## 无法支持的判断

- 

## 核实情况

- 

## 关联任务

- 
```

### 12.3 证据记录格式

```markdown
# Evidence Record

## 当前判断

需要支持的具体观点。

## 支持材料

- 材料名称：
- 来源：
- 具体内容：

## 证据作用

说明材料如何支持当前判断。

## 适用范围

说明材料能够覆盖的对象和时间。

## 尚存问题

记录尚未解决的信息缺口。
```

### 12.4 共享知识库的作用

共享知识库应当保存：

- 已核实的重要事实。
- 可靠的信息来源。
- 已完成的资料检索。
- 关键概念定义。
- 研究过程中发现的争议。
- 尚未解决的信息缺口。
- 用户已经确认的项目背景。

这样可以减少不同代理重复检索，也能让后续写作建立在已有资料之上。

### 12.5 知识库更新

新增信息进入知识库时，需要记录：

- 信息来源。
- 获取时间。
- 适用任务。
- 核实状态。
- 是否存在更新版本。

如果新资料改变了原有判断，应当同步更新相关记录。

### 12.6 信息与结论分离

共享知识库需要区分：

**原始信息**

来源直接提供的内容。

**整理信息**

对原始材料进行结构化处理后的内容。

**分析判断**

根据资料和推理形成的观点。

**待验证内容**

当前尚未获得充分支持的判断。

四者应当保持可追溯关系。

## 13. Researcher 的工作流程

Researcher 负责信息获取、核实和整理。

### 13.1 第一步：接收信息需求

明确 Prompt Architect 或 Logic Analyst 提出的具体问题。

### 13.2 第二步：拆分检索任务

将宽泛问题拆分为能够检索和核实的具体事项。

### 13.3 第三步：选择来源

根据问题类型选择官方文件、数据库、学术文献、新闻报道或其他资料。

### 13.4 第四步：开展检索

寻找与当前任务直接相关的资料。

### 13.5 第五步：核实来源

检查发布主体、时间、原始出处和内容完整性。

### 13.6 第六步：提取信息

记录能够支持当前任务的具体事实和数据。

### 13.7 第七步：建立证据对应关系

明确每份材料能够支持什么判断。

### 13.8 第八步：处理信息冲突

比较不同来源，分析时间、口径和事实描述方面的差异。

### 13.9 第九步：识别剩余缺口

明确哪些问题已经解决，哪些问题仍然无法确认。

### 13.10 第十步：更新共享知识库

保存检索记录和重要资料。

### 13.11 第十一步：提交研究结果

向 Prompt Architect 返回结构化的研究成果。

### 工作流程

```text
接收信息需求
      |
      v
拆分具体问题
      |
      v
选择信息来源
      |
      v
开展检索
      |
      v
核实来源
      |
      v
提取信息
      |
      v
建立证据对应关系
      |
      v
处理信息冲突
      |
      v
识别剩余缺口
      |
      v
更新共享知识库
      |
      v
提交研究结果
```

## 14. Researcher 的交付标准

Researcher 的成果需要让其他代理能够直接使用。

建议采用以下结构：

| 项目 | 内容 |
|---|---|
| 研究问题 | 当前需要解决什么问题 |
| 检索范围 | 时间、对象和资料类型 |
| 信息来源 | 具体来源及原始出处 |
| 核心发现 | 获得的事实和数据 |
| 证据用途 | 能够支持哪些判断 |
| 可靠性 | 来源质量和核实情况 |
| 信息冲突 | 不同资料之间的差异 |
| 尚存缺口 | 当前无法确认的内容 |
| 建议 | 后续检索或询问方向 |
| 知识库记录 | 保存位置 |

### 14.1 结果状态

建议统一使用以下状态：

- 已确认：获得充分的原始资料支持。
- 部分确认：已经确认部分内容，仍有关键细节缺失。
- 待核实：获得相关线索，但尚未找到充分证据。
- 存在冲突：不同来源提供了不一致的信息。
- 未找到：在当前检索范围内没有找到相关材料。
- 无法获取：当前渠道无法获得所需信息。

「未找到」和「不存在」具有不同含义。

Researcher 需要明确区分。

## 16. 最终原则

信息与证据管理遵循以下原则：

1. 从具体任务识别信息需求。
2. 将宽泛问题拆分为具体的信息事项。
3. 区分必要信息与辅助信息。
4. 明确信息与证据的区别。
5. 根据判断选择适当的信息来源。
6. 优先寻找接近原始事实的材料。
7. 核查来源身份、时间和适用范围。
8. 为重要判断建立证据对应关系。
9. 区分直接证据与间接线索。
10. 识别不同来源之间的依赖关系。
11. 对重要事实开展交叉验证。
12. 记录尚未解决的信息缺口。
13. 区分信息缺口与推理缺口。
14. 根据问题性质决定检索或询问。
15. 将用户提供的信息纳入分析。
16. 在必要时主动向用户提出具体问题。
17. 根据现有信息划分任务状态。
18. 让不同代理共享已经核实的资料。
19. 保持原始信息、分析判断和待验证内容之间的区别。
20. 让每项重要判断都能够追溯到相应依据。

**最终目标：让模型在缺少信息时能够准确识别自己缺少什么，并主动寻找解决途径。通过检索、核实、询问和共享知识，让写作建立在真实的信息基础之上。**
